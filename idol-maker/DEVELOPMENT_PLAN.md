# 아이돌 키우기 개발 계획

작성일: 2026-10-03 · 상태: 사용자 승인 완료 · 로컬 체험판 구현

이 문서는 승인받은 구현 순서와 검증 기준이다. 현재 구현 내용과 남은 실기기 검증은 [README](README.md)와 [검증 기록](TESTING.md)에 정리했다.
승인 후 첫 검토용 버전에서 다섯 멤버, 하루 일곱 일정, 노래·춤, 첫 데뷔, 열 개 저장 슬롯, 의상, 소리, 오프라인 실행을 직접 체험할 수 있게 한다.
이후 영화·예능·화장·작곡과 네 성장 경로를 완성한다. 첫 버전의 범위는 전체 요구를 줄이는 결정이 아니다.
최종 게임 규칙은 함께 검토할 [게임 기획서](GAME_DESIGN.md)를 기준으로 한다. 검토 결과에 따른 수치·명칭 변경은 활동 데이터에 반영한다.

## 승인한 개발 방향

- 진행 방식: 아래 여섯 단계로 만들고, 첫 체험 이후 조작감과 성장 속도를 검토한다.
- 첫 체험 범위: 단계 3 종료 시 플레이 가능한 핵심 버전을 제공한다.
- 전체 범위: 단계 4에서 모든 성장 경로와 활동을 연결하고 단계 5~6에서 완성도를 검증한다.
- 저장 방식: 독립 진행 슬롯 10개, 활성 슬롯 하루 종료 자동저장, 수동 저장, 별도 임시 복구 기록.
- 설치 방식: HTTPS로 처음 접속하여 오프라인 준비를 마친 뒤 인터넷 없이 실행한다.
- 구현 시작 전 도구·런타임의 사용 가능 버전을 확인하되 새 프레임워크나 백엔드를 기본 전제로 추가하지 않는다.

## 구현 구조

기존 저장소처럼 정적 HTML·CSS·JavaScript를 사용한다. 화면과 규칙을 분리해 규칙은 브라우저 없이도 검사할 수 있게 한다.
외부 CDN, 원격 API, 로그인, 실제 SNS 연결, 결제 기능은 필요하지 않다.
새 게임 파일은 `idol-maker/`에 모으고 기존 게임은 수정하지 않는다. 루트 게임 목록 링크는 승인된 구현 단계에서 추가한다.

| 파일·폴더 | 책임과 데이터 경계 |
| --- | --- |
| `index.html`, `styles.css` | 한국어 화면, 반응형 배치, 터치·키보드 접근성 |
| `src/main.js`, `src/ui/` | 화면 전환, 입력, 상태 표시; 직접 능력치나 보상 변경 금지 |
| `src/core/state.js` | 새 진행 생성, 상태 불변조건, 진행 버전 |
| `src/core/actions.js` | 일정 시작·완료·취소와 비용·보상의 단일 처리 창구 |
| `src/core/day.js` | 일곱 일정 제한, 하루 마감, 동료 자동 성장 |
| `src/core/progression.js` | 오디션·데뷔·승급·네 경로의 목표 판정 |
| `src/core/events.js` | 조건에 맞는 짧은 사건과 선택 결과 |
| `src/data/` | 활동·의상·장비·성격·대사·목표·경제·성장 수치 정의 |
| `src/minigames/` | 노래·춤·연기·예능·화장 입력과 결과 생성 |
| `src/storage/` | 슬롯, 복구, 검증, 마이그레이션, 충돌 처리 |
| `src/audio/`, `src/character/` | 소리 수명 관리, SD 외모·의상 레이어 조합 |
| `assets/` | 로컬 SVG·그림·음원·아이콘과 자산 출처 기록 |
| `sw.js`, `manifest.webmanifest` | 게임 폴더 범위 캐시, 설치 정보, 업데이트 |
| `tests/`, 필요 시 `build.mjs` | 중요한 규칙 검사와 배포용 자산 목록 생성 |

파일명은 구현 시 합칠 수 있지만 규칙·표현·저장 사이의 책임 구분은 유지한다.
SVG 레이어로 SD 캐릭터와 의상을 조합하고 노래 리듬 판정 화면에는 Canvas 사용을 검토한다.
Canvas를 사용하는 화면도 버튼, 설명, 일시정지와 결과는 읽기 쉬운 HTML로 제공한다.

## 상태와 저장

- `GameState`: 스키마 버전, 진행 ID, 게임 날짜, 단계, 리더 ID, 멤버 5명, 그룹 자원, 일정, 목표, 옷장·장비 보유 및 장착 상태, 설정.
- `Member`: 이름·외모·성격·레벨·노래·춤·연기·예능·매력과 성장 이력. 리더의 SNS 팔로워는 개인 지표로 저장한다.
- `Group`: 돈·인지도·그룹 팬·그룹 스트레스와 활동 해금 정보.
- `DayState`: 사용한 일정 칸, 동료 성장 완료 날짜, 하루 마감 상태, 미니게임 등장 카운터.
- `ActionRun`: 고유 실행 ID, 종류, 차지할 칸, 비용, 진행 상태, 결과, 보상 지급 여부.
- `SaveEnvelope`: 슬롯 번호, 스키마 버전, 저장 시각, 수정 순번, 진행 상태 및 검증 정보.
- 에너지 현재값과 최대값은 분리한다. 초기 60에서 성장에 따라 100까지 늘어나는 안을 데이터로 관리한다.
- 미니게임 진행 상태는 재현 가능한 데이터로 제한하며 DOM·오디오 객체는 저장하지 않는다.

일정의 상태 전이는 `대기 → 실행 중 → 결과 확정 → 반영 완료`로 단순하게 유지한다.
시작 시 비용과 일정 칸을 함께 처리하고, 결과 확정 시 같은 실행 ID의 보상은 한 번만 반영한다.
실패·취소·재도전의 비용은 기획에 맞춰 정의하고 화면에 보여 준다. 새 시도와 이전 시도의 보상 기록을 섞지 않는다.
하루 마감은 리더 행동 종료, 동료 네 명 성장, 날짜 증가와 자동저장을 하나의 검증 가능한 절차로 묶는다.
저장 후 다시 열거나 중간에 탭이 닫혀도 동일 날짜 동료 성장이 두 번 실행되지 않아야 한다.

정식 자동저장은 활성 슬롯의 게임 하루 종료 시 한 번 실행한다. 수동 저장은 현재 슬롯을 갱신하거나 다른 슬롯에 복사한다. 복사 저장에 성공하면 이후 자동저장 대상도 새 슬롯으로 전환한다. 다른 진행을 덮어쓸 때는 대상 이름과 날짜를 보여 주고 확인한다.
행동 시작·결과 반영 등 복구가 필요한 경계의 임시 기록은 정식 슬롯 수에 포함하지 않는다.
노래·춤 도중 창을 닫았다가 복원하면 같은 패턴으로 해당 활동 시작부터 다시 진행한다. 같은 화면에서 일시정지했다가 돌아오는 경우에는 멈춘 지점에서 재개한다.
동일 시도 재개는 비용·일정 칸을 다시 차감하지 않는다. 취소하면 칸·비용을 환원하고 보상은 지급하지 않으며, 제안된 미니게임·패턴을 유지한다.
복구 기록은 진행 ID·슬롯·수정 순번을 확인하고 정식 저장보다 최신일 때만 복구 후보로 제시한다.
슬롯 변경·새 게임·불러오기 전에 현재 진행을 처리해 다른 슬롯의 복구 기록이 섞이지 않게 한다.

`localStorage`는 origin별로 유지되므로 같은 배포 주소를 사용한다. 브라우저 데이터 삭제 시 저장이 사라질 수 있고 `file://`의 저장 동작은 보장하지 않는다. [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)
저장 거부·용량 부족·손상 시 성공했다고 표시하지 않고 한국어로 상태와 재시도 방법을 보여 준다.
로드는 검증한 임시 상태에서 완료한 뒤 현재 상태를 교체한다. 읽을 수 없는 기록을 자동으로 덮어쓰지 않는다.
스키마 변경에는 이전 형식의 변환 함수를 두고 변환 실패 시 원본 기록을 보존한다.
두 탭이 같은 슬롯을 쓰면 수정 순번과 다른 탭 알림으로 충돌을 감지하고 뒤늦은 덮어쓰기를 막는다.
저장 키와 임시 기록 키는 모두 `idol-maker` 접두사로 격리한다.

## 단계 1 · 기획 확정

작업 크기: 작음. 의존성: 사용자 기획·개발 계획 검토.

- 능력치, 하루 일곱 칸, 활동 비용, 에너지 성장, 데뷔 조건과 네 경로 목표를 데이터 표로 옮길 준비를 한다.
- 미니게임 등장 간격, 실패 후 재도전 방식, 저장 중 미니게임 복원 방식을 결정한다.
- 이름·외모·의상, 주요 화면 흐름과 첫 15분의 목표를 확인한다.
- 영화 연기를 범위로 유지한다. 드라마 확장은 별도 기획 검토 전 구현 목록에 넣지 않는다.
- 산출물: 확정 규칙 표, 화면 흐름, 최초 자산 목록과 이후 단계의 작업 목록.
- 사용자에게 보일 결과: 첫 시작부터 데뷔까지 어떤 화면과 선택을 만나는지 알 수 있는 검토 자료.
- 완료 기준: 기획과 개발 계획의 모순을 해소하고 사용자가 구현 진행을 승인한다.

## 단계 2 · 기반과 저장

작업 크기: 중간. 의존성: 단계 1 승인.

- 정적 앱 뼈대, 데이터 정의, 순수 규칙 함수, 입력 공통 처리와 테스트 실행 경로를 만든다.
- 다섯 멤버와 리더 선택·꾸미기 정보를 초기 상태에 넣고 하루 일곱 칸 모델을 구현한다.
- 일반 훈련·무료 훈련·휴식, 자원 차감, 에너지 최대치, 그룹 스트레스의 기본 계산을 만든다.
- 열 개 슬롯과 정식 저장·임시 복구·불러오기·스키마 검증·같은 슬롯 충돌 처리를 연결한다.
- 미니게임 실행 ID와 결과 확정 구조를 먼저 만들어 이후 게임들이 같은 보상 경로를 사용하게 한다.
- 산출물: 실제 슬롯 선택 화면, 기본 일정 화면, 초기 캐릭터 표시, 핵심 규칙 검사.
- 사용자에게 보일 결과: 새 진행을 만들고 훈련·휴식한 뒤 슬롯별로 저장하고 이어 하기.
- 완료 기준: 자원 0에서 회복 가능, 일곱 칸 초과 불가, 동료 하루 한 번 성장, 독립 슬롯 복원이 확인된다.

## 단계 3 · 첫 체험 버전

작업 크기: 큼. 의존성: 단계 2의 상태·저장 경계 검증.

- 노래 리듬과 춤 방향 미니게임을 만들고 일반 훈련 사이에 가끔 등장하게 한다.
- PC 키보드와 iPad 터치가 같은 판정 규칙을 사용하도록 입력을 변환한다.
- 미니게임 결과, 실패 후 재도전·회복, 오디션 합격을 통한 첫 데뷔를 연결한다.
- 성격에 따른 기본 대사·성장 차이와 짧은 사건, 나머지 네 멤버의 하루 성장 요약을 보여 준다.
- 기본 외모 선택과 소수의 상점 의상을 실제 캐릭터 레이어에 적용한다.
- 연습실·숙소·소속사·첫 무대, 밝은 BGM·효과음과 음소거 설정을 연결한다.
- 서비스워커와 최소 설치 정보를 제공하고 전체 초기 자산의 오프라인 준비 상태를 보여 준다.
- 산출물: 약 15분 단위로 끊어 이어 할 수 있는 첫 데뷔 체험 버전.
- 사용자에게 보일 결과: 다섯 멤버 그룹을 만들고 리더를 육성하여 데뷔한 뒤 저장·오프라인 재실행.
- 완료 기준: 열 개 슬롯, 의상, 소리, 노래·춤, 오디션, 데뷔와 기본 오프라인 흐름이 함께 동작한다.
- 검토 항목: 9세가 읽고 조작할 수 있는지, 난이도와 텍스트 길이, 성장 속도, 터치 버튼 크기.
- 이 검토는 이후 기능의 삭제 승인이 아니다. 전체 범위는 다음 단계에서 계속 완성한다.

## 단계 4 · 활동과 성장 확장

작업 크기: 큼. 의존성: 단계 3의 첫 체험 피드백 반영.

- 안무 기억, 연기 감정·대사, 예능 반응 선택, 화장 자유 꾸미기를 공통 실행·저장 체계에 추가한다.
- 화장은 미학 점수 없이 참여 보상을 주고 완성한 모습이 캐릭터에 반영되게 한다.
- 작곡과 곡 발표를 싱어송라이터 경로의 실제 선택·성장 활동으로 연결한다.
- 방송·음원·영화·광고·콘서트·행사·게임 속 유튜브 스트리밍의 조건·비용·보상을 데이터화한다.
- 첫 콘서트, 연말 연기대상, 관객과 SNS 성과를 확인 가능한 목표와 결과 화면으로 연결한다.
- 대형 소속사 오디션과 인기·톱·월드스타 진급을 구현한다.
- 배우·예능·무대·싱어송라이터 네 경로 모두 월드스타까지 갈 수 있도록 별도 완료 검사를 둔다.
- 돈·행동력 경제와 무료 훈련·휴식의 균형을 조정하고 상점 의상·장비 구매와 착용·사용 효과를 완성한다.
- 운동·피부관리·미용·식단 관리와 놀기·먹기·휴가·게임을 활동 데이터에 포함하고 그룹 스트레스 회복을 연결한다.
- 캐스팅·예능 화제·팬 반응·선택 사건을 확장하고 성격이 대사와 사건에도 영향을 주게 한다.
- 월드스타 이후 반복 목표와 새로운 기록을 제공해 게임오버 없이 계속 육성할 수 있게 한다.
- 산출물: 전체 성장 경로, 활동·사건 데이터, 장기 목표와 경제 수치의 첫 완성본.
- 사용자에게 보일 결과: 선호하는 활동을 골라 여러 방향으로 성장하고 월드스타 이후에도 이어 하기.
- 완료 기준: 모든 요구 활동에 진입·결과·회복 경로가 있고 네 경로에 막히는 승급 조건이 없다.
- 범위 확인: 연애·친밀도, 실제 결제, 외부 SNS 연결, 접속하지 않은 시간의 자동 진행이 없다.

## 단계 5 · 화면과 자산 완성

작업 크기: 중간. 의존성: 단계 4의 화면·활동 목록 안정화.

- 라벤더·민트·크림·하늘색을 중심으로 SD 캐릭터와 화면을 통일하고 분홍색은 적게 사용한다.
- 산출 자산: 기본 몸·얼굴·머리·표정, 외모 선택, 의상 레이어와 미리보기, 작은 동작·감정 표현.
- 산출 배경: 연습실·숙소·소속사·무대·촬영장과 각 활동의 결과 카드.
- 산출 소리: 밝은 반복 BGM, 결정·성장·성공·실패 효과음, 노래 미니게임 음원과 박자 데이터.
- 자산별 파일명·용도·제작 또는 이용 출처를 남기고 배포에 필요한 파일을 모두 로컬에 둔다.
- 실패 안내는 재도전·회복을 안내하는 짧은 한국어로 작성한다. 색상만으로 상태를 구분하지 않는다.
- 긴 이름·큰 글자·좁은 화면에서도 버튼·저장 안내·자원 수치가 가려지지 않게 다듬는다.
- 산출물: 임시 자산을 교체한 전체 화면과 오디오, 완성된 자산 목록.
- 사용자에게 보일 결과: 모든 장소와 활동에서 일관된 캐릭터·의상·소리·성장 연출.
- 완료 기준: 착용 상태가 관련 화면에 일치하고 필요한 자산 누락 없이 오프라인에서 표시·재생된다.

## 단계 6 · 기기 검증과 배포 준비

작업 크기: 중간. 의존성: 단계 5와 실제 iPad Safari 검증 환경.

- PC 브라우저의 키보드·마우스와 iPad Safari의 터치·가로세로 전환·홈 화면 실행을 검증한다.
- 실제 기기의 리듬 판정·오디오 지연·드래그·스크롤 충돌을 확인하고 입력 여유를 조정한다.
- 탭 이탈·화면 잠금 때 진행과 오디오를 일시정지하고 복귀 시 안내 후 재개한다.
- 오프라인 준비 실패·캐시 업데이트·서브경로 배포·재시작·저장 거부 상황을 검증한다.
- 활성 게임 중 업데이트를 강제 적용하지 않고 저장 뒤 안전한 시점에 새 버전을 적용한다.
- 루트 게임 목록에 링크를 추가하고 기존 두 게임과 저장·캐시가 충돌하지 않는지 확인한다.
- 산출물: 배포 파일, 검사 결과, 짧은 실행·저장·오프라인 안내, 남은 제한사항.
- 사용자에게 보일 결과: PC와 iPad 각각의 기기·브라우저에 저장하여 이어 할 수 있는 완성본과 검증 내역. 기기 간 자동 동기화는 포함하지 않는다.
- 완료 기준: 아래 중요 행동 검사를 통과하고 실제 기기에서 발견한 진행 차단 오류를 해결한다.
- 실기기 접근이 없으면 해당 검사는 미확인으로 남긴다. 에뮬레이션만으로 iPad 검증 완료를 선언하지 않는다.

## 작업 크기와 모델 사용

이 계획의 크기는 상대적인 작업량이며 완료 날짜·실시간 작업 시간·토큰 절감률을 보장하지 않는다.
이번 기획은 `gpt-6-astra / xhigh`, 개발 계획은 `gpt-6-astra / medium`으로 분담한다.
승인 후 작은 구현은 요구한 Light를 낮은 추론 강도 `low`로 해석해 사용하고, 짧은 작업과 필요한 변경분만 전달한다.
저장 원자성·리듬 타이밍·오프라인 오류처럼 어려운 문제는 `medium`으로 높이고 큰 기획 변경에만 `xhigh`를 다시 사용한다.
실제 구현을 시작할 때 선택 가능한 모델·강도를 확인한다. 이 문서만으로 현재 채팅 모델이 자동 변경되는 것은 아니다.
첫 체험 검토 뒤 다음 작업 묶음만 구체화하고 이미 확정한 기획 전체를 반복 분석하지 않는다.

## 검토할 전제

하루 일곱 칸, 초기 에너지 60→최대 100, 열 개 독립 저장 슬롯과 임시 복구, 영화 중심 연기를 검토할 기본안으로 삼았다.
게임 기획서의 보상·성장 기간은 검증 전 조정값이다. 모의 진행으로 네 경로의 소요일·돈·팬 증가를 비교하고 실제 첫 체험 피드백으로 확정한다.
게임 날짜 기준 행사와 오프라인 중 진행 정지, 리더의 개별 SNS와 그룹 팬 구분을 유지한다. 드라마는 검토 보류다.
저장 내보내기·가져오기 같은 추가 기능은 이번 필수 범위로 가정하지 않았다.
사용자의 기획 검토 및 구현 승인을 받아 로컬 체험판을 만들었다. 배포는 별도 요청 시 진행한다.
